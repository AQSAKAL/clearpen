# Plan: the writing app in the desktop app

**Status:** approved 2026-10-26. Milestones 1 (Write), 2 (Edit with AI) and 3 (Next sentence) are built; at your request the next sentence moved up, ahead of checks and review, which come next.

## Context

The desktop app installs and runs, but it only shows a check screen. You still write in the prototype: a browser app (`margin/`) with a Node server that keeps articles as JSON files. This plan builds the real writing app into the desktop app:

- **Interface:** shadcn/ui.
- **Editor:** CodeMirror.
- **Engine:** `@margin/core`, running inside the app.
- **Storage:** projects and articles in the SQLite library.

It brings forward the parts of phases 2 and 3 in [the architecture](../ARCHITECTURE.md) that the desktop app needs.

**The bar:** everything the prototype does, the desktop app does too. Two surveys of the prototype listed every feature, shortcut and server call; the parity list at the end comes from them. A few deliberate changes are listed under [Decisions](#decisions).

## How it fits together

```
apps/desktop     Tauri shell + LocalBackend (SQLite, core, Ollama, files)
packages/ui      the app in React + shadcn/ui; talks only to a Backend interface
packages/editor  CodeMirror 6: Markdown, ghost text, suggestions, notes, images
packages/db      Drizzle schema (SQLite), migrations, repositories
packages/core    the engine (exists): checks, prompts, AI tasks
```

- **`Backend` interface:** defined in `packages/ui`. The UI never calls Tauri, SQLite or Ollama directly.
  - **`LocalBackend`** (desktop) runs `db` and `core` in the app. AI goes through the HTTP plugin, using the `localFetch` from today's shell.
  - **`MemoryBackend`** keeps everything in memory and calls Ollama with plain `fetch`. It is used for tests and for running the UI in a browser while developing.
  - **`RemoteBackend`** (web/server, phase 4) slots in later.
- **AI tasks stay async generators.** `rewrite`, `edit`, `check`, `review` and `ask` stream events straight into React. There is no SSE layer on the desktop.
- **Logic the prototype keeps in the browser moves into `core`**, so the web app gets it too:
  - the post-processing in `selection.js` (re-splitting big edits, "unverified figure" warnings);
  - in `check()`: Margin's own findings per lens first, and model items that overlap a numbers finding suppressed;
  - review notes re-anchored to the current text, and duplicates dropped;
  - `notesMarkdown` and the coach titles.

### Data (`packages/db`)

Portable types, as the architecture requires: UUIDv7 ids as text, times as integer milliseconds, JSON as text, and `created_at`, `updated_at` and `deleted_at` on every row.

| Table | Holds |
|---|---|
| `projects` | name, slug, publishing settings (JSON, unused for now) |
| `documents` | title, content (Markdown), brief (JSON), meta (JSON), project, **words** and **excerpt** (stored on save so the library list is instant), status |
| `versions` | snapshots: label, title, content, words. Kept to 60, thinning the oldest unlabelled first; a version identical to the last isn't saved |
| `media` | sha-256, type, size, file name |
| `settings` | key → JSON: models per role, Ollama URL, theme, fonts, next-sentence on/off, collapsed projects, last article, drawer tab |

- **Driver:** Drizzle's `sqlite-proxy`, wired to the Tauri SQL plugin.
- **Migrations:** plain SQL files generated by drizzle-kit and bundled into the app. A 40-line migrator applies them in order and records each in a `migrations` table. The same migrator runs in tests and in the app, so the tested path is the shipped path.
- **Tests:** every repository is tested against real SQLite (Node's built-in `node:sqlite`) through the same proxy driver.
- **Images:** stored as files in the app's data folder, `media/<sha>.<ext>`, using the Tauri file-system plugin, scoped to that folder only. They're shown through Tauri's asset protocol, which the CSP already allows. In Markdown an image is `![alt](media/<sha>.png)`, which stays valid when you export a folder.

### Editor (`packages/editor`)

A TypeScript port of the prototype's `editor-src/index.js` (641 lines), keeping its `createEditor(parent, opts)` API and its behaviour:

- **Text:** Markdown styling and line classes, image previews, find.
- **AI marks in the text:** ghost text and the "¶ point made · Tab for new paragraph" hint; tracked suggestions with ✓/✕, groups, warnings and Accept all; note underlines; analysis highlights.
- **Writing aids:** focus mode, and the "◇ Shape this section" button.
- **Keys:** Tab never leaves the editor; it accepts, indents or does nothing, and Esc then Tab within 1.5 s moves focus on. Also ⌘→, ⌘↵, Esc, ⌘J, ⌘B and ⌘I.
- **Next-sentence trigger:** today it lives in the prototype's `complete.js`. It moves here as a plugin, using core's constants. It waits 650 ms, needs 25 characters of your own between suggestions, cancels by sequence number, and puts only one AI item on screen at a time.
- **Tests:** on the state fields (suggestion mapping, ghost clearing, notes mapping) and on the keymap.

### Interface (`packages/ui`, shadcn/ui only)

| Region | Built from |
|---|---|
| Library sidebar: projects (titles only, collapsible, + and ⋯), loose articles, search, drag to move, Trash | `Sidebar`, `Collapsible`, `DropdownMenu`, `Input`, `ContextMenu` |
| Top bar: save state, word count, Read, Review, Assist, ⋯ | `Button`, `Tooltip`, `DropdownMenu` |
| Title and editor | `Textarea` (auto-size) + `packages/editor` |
| Selection toolbar: Improve, Shorten, Simplify, Fix grammar, What's missing?, Check ▾, Tone ▾, Ask AI to… | `Button`, `DropdownMenu`, `Input` in a positioned bar |
| Slash menu: think aids, formatting, Ask | `Command` (cmdk) in a `Popover` |
| Margin notes: review, check and coach cards beside their passages | `Card`, `Badge`, `Button` |
| Assist panel: Plan, Notes, Ask, Insights, Publish | `Tabs`; an inline column when wide, a `Sheet` when narrow |
| Status, progress, Undo, Accept all / Reject all | `Sonner` toasts + a small status pill |
| Dialogs: models, fonts, history, shortcuts, confirmations | `Dialog`, `AlertDialog`, `Select`, `ScrollArea`, `Kbd` |
| Reader mode | core's Markdown renderer, styled with Tailwind Typography |

- **Theme:** shadcn's tokens, set to Margin's paper-and-ink palette, with light, dark and system modes.
- **Layout:** the prototype's three widths (wide, medium, narrow).
- **On Mac:** the title bar overlays the sidebar.
- **Fonts:** bundled, so they work offline.

## Milestones

Each milestone ends with an app you can install and try, all checks passing, and a commit on a new branch, `phase-3/writing-app`.

1. **Write.** You can write in the desktop app.
   - **Packages:** `packages/db`, `packages/editor` (text features) and the shadcn setup in `packages/ui`.
   - **Library:** projects and articles, create/rename/move, search, and Trash with restore.
   - **Editing:** title and editor, autosave, word count, versions (⌘S, every 10 minutes, history with restore), reader mode, focus mode, image paste and drop.
   - **Look:** theme and fonts.
   - **Out:** copy as Markdown or rich text, and save as .md or .html.
   - **Start:** a welcome article on first launch.
   - **Retired:** the check screen. The Ollama status moves into the models dialog.
2. **Edit with AI.**
   - **Models:** the models dialog (Ollama status, a model per role) and the status in the sidebar.
   - **Selection:** the toolbar with presets, tones and free instructions, including the "edits, never writes from scratch" refusal.
   - **Suggestions:** tracked, with per-change ✓/✕, Accept all / Reject all and integrity warnings.
   - **Control:** Esc stops any AI task.
   - **Safety:** a version is saved before you accept AI changes.
3. **Next sentence (autocomplete).** Moved up from Think.
   - **Ghost text:** the one sentence a paragraph is missing, after a finished sentence and a pause, or on ⌘J. Tab keeps it, ⌘→ takes one word, Esc or typing on dismisses it.
   - **The paragraph hint:** "¶ point made · Tab for new paragraph" when the paragraph is complete.
   - **The rules:** your own words must come between suggestions, and no suggestion appears while other AI changes are on screen. There's an on/off switch in the ⋯ menu.
4. **Check and review.**
   - **Review:** it shows Margin's own checks for the whole draft instantly, then the AI's notes. Cards sit in the margin, or in the Notes tab when narrow.
   - **Selection checks:** fact-check, logic and consistency, with the second-opinion pass.
   - **Insights:** stats, reading level, the six highlight kinds, and structure.
5. **Think.**
   - **Slash menu, coach notes and Shape this section,** with "Add to my notes".
   - **Ask:** a chat about the draft.
   - **Plan:** brief, sections map, outline and headlines.
   - **Publish:** description, slug, tags, excerpt and social post.
6. **Ship 0.2.0.**
   - **Checks:** a keyboard and accessibility pass, and the narrow layout.
   - **Export everything:** a folder of Markdown files plus media.
   - **Out:** updated docs, a version bump and a locally verified build. The release is tagged only when you say so.

**Can run side by side:** `packages/db` and `packages/editor` are independent of each other in milestone 1. The UI starts once both interfaces exist.

## Decisions

Changes from the prototype or the architecture, for your OK:

1. **Postgres comes with the server (phase 4), not now.** The schema uses portable types, so the Postgres version is a translation. Writing it now would mean maintaining a dialect nothing uses yet.
2. **No router yet.** The app is one screen, and the open article goes in the URL hash. TanStack Router can come with the web app.
3. **Fonts are bundled, not loaded from Google Fonts.** The app must work offline, and its CSP blocks outside fonts. You get a curated set of about eight serif, sans and mono fonts, but not "any Google Font".
4. **The prototype's `writer` model is gone.** Nothing used it. Core's roles are quick, coach and checker.
5. **Fixes to prototype gaps:**
   - Trash can be viewed and restored;
   - search covers the full text;
   - a version is saved before accepting AI changes;
   - Review includes Margin's own checks (compliance and procedure findings were never shown before);
   - the theme can follow the system.
6. **Kept as in the prototype:** Ask chats live only while the app is open, and every setting moves into the library file.

## Verification

- **`pnpm check`:**
  - unit tests for `db` (real SQLite), `editor` (state and keys) and the new `core` helpers;
  - component tests for `ui` against `MemoryBackend`, with Testing Library and happy-dom.
- **In the browser pane:** the desktop UI runs on `MemoryBackend` with real Ollama, which allows `localhost` origins. I click through each milestone's features and take screenshots, against the parity list below.
- **In the built app:**
  - install it, and confirm articles, versions, settings and images land in the library file and the `media` folder (`sqlite3` checks);
  - check that a version survives a restart;
  - check that the AI streams through the HTTP plugin.
  - The Tauri window can't be driven automatically on a Mac, so you try each milestone's build yourself.

## Parity checklist (from the prototype)

**Library**
- New article; new project, which also creates an article in it.
- Projects: rename and delete; deleting one keeps its articles.
- Moving articles: drag onto a project or onto "Articles", or ⋯ → Move to project…
- Collapsed projects are remembered. Search shows matching projects expanded.
- Trash.
- Opens the last article on launch.

**Editor**
- Title: Enter or ↓ moves into the text.
- Markdown styling; images.
- Find: ⌘F.
- Focus mode: ⌘.
- Versions: ⌘S, and every 10 minutes.
- Reader mode: ⌘⇧P, Esc or double-click to leave.
- Library toggle: ⌘\.
- Word count and reading time.
- Empty-article hint with "Plan this article" and "Just write".

**AI**
- Rewrite presets: Improve, Shorten, Simplify, Fix grammar.
- Tones: More formal, More conversational, More confident, More persuasive, Active voice, Make it a hook.
- Free-instruction edits, which refuse to write from scratch.
- Checks: fact-check, logic, consistency.
- Review: ⌘⇧E.
- Ask, with starter questions.
- Think aids: next, opening, ending, examples, counter, ideas, point, deepen, shape.
- Headlines, outline, meta.
- Next sentence: Tab, ⌘→, ⌘J, Esc; toggled from ⋯.

**Insights**
- Stats; reading grade and Flesch score.
- Highlights: very long sentences, long sentences, passive voice, adverbs, filler, clichés.
- Structure (the headings, clickable).

**Settings**
- Models per role, Ollama status.
- Theme, fonts, next-sentence toggle.
- Keyboard-shortcuts dialog.

**Out**
- Copy as Markdown, copy as rich text.
- Save as .md, save as .html.
- Copy buttons for each Publish field.
